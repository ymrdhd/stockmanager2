# 产品与技术需求规格书（PRD / SRS）

- 状态：v2.0 架构基线；交付目标调整为最小可用 V1.0（ADR-013）。实际开发与验收状态见 STATUS。
- 适用：仅一个人使用；投资决策、真实交易管理、个人财务同等重要。
- 事实来源：`LEGACY_BASELINE.md` 记录的**现行入口**；旧仓库历史代码≠当前功能。不得恢复五资产配置。

## 版本范围（已批准）

V1.0：唯一正式库、真实成交/批次/成本/当日收益/累计盈亏、现行 V9/G2 与行情更新、财务账户/收支账本/净资产/财务月、基础 Web、公司服务/家里远程浏览器/本地独立启动、备份/恢复及旧库迁移。

V1.5：Fed 利率观测器、日内盈亏分钟蜡烛图、14 只 ETF 等权参考曲线、高级投资绩效图表、精细财务图表与界面优化。V2.0 候选（尚非承诺）：券商成交批量导入、微信/支付宝批量账单导入、高级交易复盘、复杂预算及现金流预测。不提前实现延期功能或占位入口；五资产永久排除。以下功能细节仅按对应版本适用，核心数据安全和正确性要求不延期。

## 1. 成功定义

用户在家或公司打开同一个系统，可快速获知个人净资产、投资收益、持仓风险与策略变化；每一笔实际交易仅记一次；当天收益、净资产、现金流都能从事实数据解释和复算；断网不会产生第二份正式账本。系统不执行券商下单。

### 北极星与质量门槛

- 30 秒内能定位最新有效资产、持仓与待办（性能目标，不能用伪造/过期数据满足）。
- 在同一数据库版本与行情快照下，两台电脑得到同一个计算结果。
- 交易重试、重启、补录、备份恢复，不产生重复成交或收益。
- 每个关键金额可展开看到口径、来源、时间和计算状态（有效/延迟/缺失/需对账）。

## 2. 功能范围与页面

### 2.1 总览（核心数据 P1/P2，界面 06）

- 净资产、证券账户权益、投资当日盈亏、本财务月净现金流；每个卡片展示更新时间与可信状态。
- 持仓风险（止损/退出已触发或接近）、正式策略信号、待核对成交/账户差额；从问题跳到对应详情。
- 证券收益走势、个人净资产走势与投资盈亏不得混用同一个含义。
- 当日收益无有效昨收/成交数据时显示“不可计算”及原因，不显示 `0` 或旧值假装实时。
- **当日投资收益率（ADR-018，2026-11-25 正式批准）**：当日投资盈亏 ÷ 上一有效交易日收盘证券权益，**显示两位小数**；分母缺失或非正数时不计算并给出原因。该指标是基础收益率，不是 TWR/MWR，也不做年化。

### 2.2 投资（核心 P1，界面 06；Fed V1.5）

- **持仓**：按证券账户与标的查询数量、成本、现价、市值、浮动盈亏、当日盈亏及持仓批次。
- **批次**：V9/G2 主仓/加仓分别展示原始成交、信号日期、冻结 ATR、保护价位、卖出分配、状态。
- **策略观察池**：展示现行 V9/G2 标的、市场状态、候选/正式/否决、准入原因、行情完成日、新鲜度、关键价格。
- **行情**：已核实收盘/有效盘中价格、数据源、代理标签、缺口检查、手动触发刷新；过期不伪装有效。
- **市场研究（V1.5）**：现有 Fed 观察功能（EFFR、FOMC 概率、CPI Nowcast、实际利率）。仅解释研究，不回写正式策略。
- 所有交易决定由用户在券商执行，系统只提供策略状态和后续成交录入。
- **接近止损预警（ADR-020，2026-11-25 正式批准）**：持仓报价距**有效保护价 2%**（`--near-stop-bps 200`）以内时提示，**仅用于风险预警**，不改变 V9/G2 原始策略规则（不改冻结 ATR、主/子仓、信号时点、质量闸门与保护动作），不生成卖出或下单；NDX T5 继续使用其独立规则。报价未核实、过期或账本版本不一致时不提示。

### 2.3 交易（核心 P1，界面 06）

- 录入实际买/卖、费用、账户、证券、成交时间、价格、数量、券商成交 ID（可选）、`request_id`、所属策略批次（如适用）。
- 查询、按日期/账户/代码过滤、逐笔展开来源及审计记录。
- 从买入形成批次；卖出明确扣减 FIFO 或指定 V9/G2 批次（校验可卖数量）。
- 交易更正通过“撤销/冲正 + 新记录”，保留审计链；不允许页面直接改持仓数量或盈亏。
- 导入券商 CSV/Excel 属于可选后续需求，需明确批准后排期；先实现导入预览/字段映射/去重后才允许提交；不可把旧桌面复杂导入视为现有 Web 已完成能力。
- 对账：实际成交 → 批次 → 持仓 → 资金 → 收益；展示差额和处理建议，但不自动改账。

### 2.4 财务（核心 P2，界面 06）

- 账户：银行卡、支付账户、证券现金、负债、其他资产；账户金额与资金流水采用明确核算模式。
- 账本：收入、支出、手续费、内部转账、退款、账户余额调整；新增、查询、更正、审计撤销。
- **退款统计（ADR-017，2026-11-25 正式批准）**：退款冲减**原支出所属财务月**，实际到账时间单独记录（实际到账月的现金流单列，不计入收入）；手工余额不因退款自动更新；累计退款不得超过原支出。
- 净资产：总资产−总负债；证券资产由同一业务库证券现金+持仓估值导出，不能再维护一份独立持仓市值。
- **流动净资产（ADR-019，2026-11-25 正式批准）**：流动资产−流动负债。流动资产纳入现金、银行卡、支付账户和可变现证券（证券按权益只计一次），**排除受限资产**；`other_asset`/`other_liability` 等未知流动性分类必须明确提示「待确认」并停止计算完整指标，不得用已知部分冒充全额。
- 支出、收入、净现金流、财务月历史；**财务月为每月 23 日到次月 22 日**，口径可在页面展示。
- 迁移旧 Finance 时保留“手工余额与普通账单独立”语义；新自动余额模式仅在账户逐个确认后启用。
- 更复杂的账单批量导入、报销/退款关联仅经批准另立任务，不能当作首版已存在。

### 2.5 设置（P1 基础，P3 完整）

- 当前服务状态、数据库身份与模式、schema 版本、最新行情时点、备份状态、最近异常。
- 数据源凭据在服务端配置，不在 Web 明文展示；手工刷新有超时/限频。
- 一键备份、备份列表、**通过隔离的恢复演练工具验证**；正式库恢复必须人工确认并停止写入。
- 启动模式：`server` 公司正式库、`client` 浏览器远程访问、`local` 只读或测试库；禁止连接失败静默切换。

## 3. 关键业务流程与验收

**买入（示例）**：用户录入已成交买单 → 校验账户/价格/数量/交易日/唯一请求 → `TradeService` 开事务 → 增加 `trade_executions`、批次及证券现金变动、写审计和投影失效标记 → 提交 → 重算持仓/当日盈亏。请求重复提交只返回原结果。

**卖出（示例）**：校验可卖数量和指定批次 → 一次事务写卖单、批次分配、现金变化、费用及审计 → 持仓和已实现收益重算；不允许先写持仓再补成交。

**跨账户资金转账**：银行向证券账户转入资金 → 双边等额资金流水相互引用 → 银行减少、证券现金增加 → 个人净资产不变、投资收益不变。

**历史补录**：补录旧日期成交 → 标识起始日期后的批次、现金、日度权益及收益快照失效 → 有序重算 → 对账通过才解除数据异常标志；不修改原始行情事实。

**断网**：家里远程页面显示服务不可达和最后数据时间 → 禁止写正式成交 → 可读本机已标记过期的缓存（如果明确开启）→ 恢复后重新读中心事实，不上传本地可写交易账本。

## 4. 质量与非功能要求

| 属性 | 要求与验收方式 |
|---|---|
| 正确性 | 强制测试交易幂等、批次守恒、资金守恒、收益重算与恢复对账 |
| 稳定性 | 重启不改变账本/收益；后台任务失败不阻塞主要只读页面；错误显式暴露 |
| 性能 | 本地首页目标 < 3s（非冷启动、缓存有效情况下）；大量历史数据使用索引和分页，性能基准可复现 |
| 数据边界 | 价格/时间/来源/交易时区明示；行情失效时不出正式买点 |
| 安全 | 仅私网访问；Web 写操作需认证、同源/CSRF 校验；无公网数据库端口 |
| 运维 | 单实例后台调度；结构迁移可备份、可预演、失败阻断启动 |
| 可恢复性 | 每日一致性备份，多版本加密保存，至少有一份独立位置副本；定期演练恢复 |
| 可维护性 | 模块化单体、强类型、可复算、API 契约测试，文档按任务路由 |

## 5. 明确不做（禁止 Agent 擅自引入）

- 五资产配置及历史旧研究功能复活。
- 自动券商下单、多账户多用户授权平台、微服务与云原生集群。
- 家/公司两份正式 SQLite 双向合并、运行中 SQLite 文件直接同步。
- 用 AI 推测正式 V9/G2 信号或替换可复算规则。
- 未被确认的旧桌面功能“顺手全量搬迁”。

## 6. 开发里程碑与交付门槛

| 里程碑 | 内容 | 退出条件 |
|---|---|---|
| P0 基线 | Repo/Agent 规范、运行入口、配置、DB 身份、迁移工具、基准测试 | 不会误连或默默创建正式空库；可生成审查包 |
| P1 投资闭环 | 成交/批次/现金、持仓、收益、V9/G2、行情、总览与交易 Web | 全套交易/收益不变量通过，能凭夹具从成交到总览追溯 |
| P2 财务闭环 | 账户/转账/财务月/账本/净资产、证券估值投影、旧库转换 | 资产守恒、财务月、余额模式与旧库对账通过 |
| P3 完善 | 备份演练、异地 Web、安全加固 | 公司/家里同一数据、断网失败关闭、恢复演练通过 |
| P4 切换 | 旧生产数据迁移、并行核对、历史报告回归、原系统只读归档 | 有真实旧库时逐项签字；不依赖旧桌面写入 |

里程碑顺序允许因风险微调，但**不得先建设华丽界面再补交易约束**。
