# Stock Manager 2.0 — 从零开发到交付的 Agent 执行计划

- **状态**：执行路线 v2.0（规划，不代表阶段已完成）。
- **功能基线**：以 `PRODUCT_SPEC.md` 的 V1.0 范围（ADR-013）和 `LEGACY_BASELINE.md` 为准；只迁移已批准的旧项目当前 Web 可达功能；**五资产配置已下线**，不恢复。
- **架构基线**：`ARCHITECTURE.md`、`DATA_CONTRACTS.md`；公司一台正式服务端、单个 SQLite 业务库、家里远程浏览器；本地沙盒/只读模式保留。
- **工作协议**：`AGENTS.md` + `AGENT_WORKFLOW.md`；每轮仅完成一个可验证目标、完成后增量打包等待审查。
- **验收唯一依据**：`ACCEPTANCE_TESTS.md` 中的测试 ID + 本文件各阶段退出门槛。本文件是进度执行计划，不重复定义数据表、公式或算法。

## 0. 完成的定义（Definition of Done）

正式交付必须同时满足：

1. 四主页面（总览、投资、交易、财务）与系统设置在打包部署中可使用；投资里包含当前有效的 V9/G2 观察池、行情；财务有历史财务月。
2. `trade_executions` 是唯一真实成交事实；统一 TradeService 事务写入；持仓、当日 P&L 和净资产可追溯、可重算且同版本一致。
3. 真实成交、批次、证券现金、普通财务账户、净资产的对账用例通过；坏数据必须显式告警，不能用“0”替代缺失。
4. 公司电脑正式服务端可启动、可开机恢复；家里通过私有 HTTPS 浏览器访问；失联拒绝写入，不自动切库。
5. 完成安全验收、一次隔离备份恢复演练、升级/回滚演练；提供 Windows 安装与操作手册。
6. **仅当取得可靠旧 `stock_manager.db` 和 `finance_manager.db` 的备份并逐项核对通过**，才能声明旧数据迁移验收完成。缺少真实数据库时只可交付“空库可用/模拟数据已验证”，不能宣称无损迁移。
7. 发布 Git tag 和版本说明，旧程序正式写入锁定；正式数据库与源代码分离且不进入审查 ZIP。

## 2. 各阶段的工作包

### P0：可靠地搭好基础（00–01）

- 完成唯一正式 SQLite、数据库身份、绝对路径、schema 迁移、不可静默创建正式库；建立 `local` 只读/沙盒模式。
- 初始化最小 API、pytest/ruff/类型检查、依赖锁和仓库忽略规则；不用提前创建大量空业务模块。
- 初步可用的备份：SQLite Backup API 生成一致性快照、验证 integrity_check，且与正式写入并行安全；后续再增加远端加密保留策略。
- **Gate P0**：本地启动/拒绝错误库/拒绝双写进程/DB 升级失败保护、审查包安全过滤全部通过。未过不得录入真实成交。

### P1：必须先形成投资最小闭环（02–04）

- `02`：先为买单/卖单/更正建可重复测试，用同一事务写成交、批次、证券现金、审计；引入唯一请求号与券商成交号约束。
- `03`：以有效报价和成交事实重建持仓、昨日基准与当日盈亏；重启与重算不修改原始资金；金额与缺失数据处理遵守 `DATA_CONTRACTS.md`。
- `04`：只迁移现行 V9/G2 规则；先收集“输入、策略版本、日期、预期输出”的黄金样例，再接行情和策略证据存档。无黄金样例不得凭历史文档猜阈值。
- **Gate P1**：T/P/S 核心用例通过；从录入买入 → 批次 → 估值 → 当日盈亏 → 风险提示可全链路追溯；有数据缺口则明确显示不可计算。

### P2：财务与投资共用事实（05）

- 账户/账本/余额调整保持历史 `manual_snapshot` 语义；新增 `ledger` 自动余额模式必须通过显式启用与完整核对。
- 内部转账双边分录；证券现金/持仓市值只计入个人资产一次；收入、支出、投资盈亏区分。
- 每月 23 日至次月 22 日、跨年与闰年有自动测试；Finance 历史数据转换在临时库演练。
- **Gate P2**：F 组及 P04/P05 用例通过；净资产、现金流、财务月与交易账本对得上。

### P3：网页完整可用、可安全异地访问（06–08 的部署部分）

- 只建一个 Vue SPA：总览、投资（含持仓/V9G2/行情）、交易、财务（含财务历史）、设置；保留来源时间与质量显示。
- 前端只调用 API，不做本地独立权威收益计算；交易提交失败/冲突/重复点击有明确反馈。
- 公司 Windows 仅运行一个正式 Web+SQLite 写实例，监听 loopback；Tailscale Serve 私有 HTTPS；家里浏览器访问同一服务。
- 登录/Origin/CSRF/Host/WS 安全校验完整；远程断网只读显示，不自动写本地库。公司电脑的公司 IT 授权是外部前提。
- 补上加密多版本备份、隔离恢复演练与故障/数据质量面板。
- **Gate P3**：完整端到端流程 + 实际双机测试 + I03/I05/I06/I07/I08 + 安全、恢复用例通过。

### P4：旧数据迁移与发布切换（08 的迁移部分 + 09）

1. **取得正确备份**：旧股票/财务 SQLite 只读副本及来源哈希；不使用原数据库直接试验迁移。
2. **迁移到新临时库**：保留原始 ID、成交、批次、手工余额和账单语义；不能把孤立的持仓伪造为实际成交。
3. **分层对账**：交易笔数/份数/费用 → 批次/持仓 → 证券现金/收益 → Finance 账户/财务月/净资产。
4. **人工处理差异**：每个差异记录旧来源、新计算、差值、裁决与证据；重大差异没关闭不能切换。
5. **并行验证**：新系统以只读方式复算历史，同期旧系统只作对照；**任何时刻只能有一个可写正式系统**。
6. **冻结与切换**：备份旧库、停止旧写入口、确认新服务唯一库身份、升级并记录 generation、执行冒烟测试。
7. **回滚方案**：新系统故障时停止新写入，再恢复到经验证的单一正式版本；不把两个分叉账本按文件时间覆盖。
8. **Release Gate**：全部阻断测试、实际数据核对、备份恢复、安全和双机检查通过后标记 `v1.0.0`；否则仅标记 RC，不宣称生产可用。

## 3. 每轮 Agent 的固定执行协议

> 与 `AGENTS.md` 和 `AGENT_WORKFLOW.md` 完全一致，后者是操作细则。

1. **接任务**：只读根 `AGENTS.md`、`docs/STATUS.md`；`docs/INDEX.md` 选本任务专题。读目标模块和测试，禁止每轮全文扫描、全仓打印。
2. **开工前**：`BASE=$(git rev-parse HEAD)`（Windows PowerShell：`$base = git rev-parse HEAD`）；在 `STATUS.md` 写目标、触碰范围、通过条件。
3. **实现**：先补对应测试或失败复现，最小修改使测试通过；遇到口径不明停止该边界并提出可裁决差异，不能自行改变 V9/G2 / 财务公式。
4. **自检**：先局部测试，再受影响回归；阻断测试失败则不申请发布。必须报告 `PASS/FAIL/NOT RUN` 和实际命令。
5. **文档**：仅更新 `STATUS.md`、真正受影响的唯一契约文档；架构决策变化才更新 `DECISIONS.md`；不要复制全文到多个 MD。
6. **审查包**：`python tools/package_changes.py --base "$BASE" --summary "..." --tests "..."`。必须含本轮新增/修改文件、删除/重命名单、manifest SHA-256、REVIEW 以及风险/回退；不得含 DB、密钥、用户数据、备份、缓存。
7. **停止并审查**：提交审查包，待人工/模型审查结论；如要修正，用同一个 BASE 重新打包本轮完整增量，而非仅打补丁包。仅 APPROVED 或 APPROVED_WITH_ISSUES（后者记录 ISSUES）才开启下一轮；不豁免正式发布核心安全及数据验收。
8. **结束汇报**：`范围 | 基准提交 | 改动文件 | 测试 | 已知风险 | ZIP 路径`，简短可追溯。

### 审查结论（由独立审查者/产品负责人裁决）

- `APPROVED`：满足本轮验收并无阻断项，可进入下一轮。
- `APPROVED_WITH_ISSUES`：允许推进，实际未完成事项记录于 ISSUES；不视为通过未执行或失败的测试，不豁免正式发布核心安全/数据验收。
- `CHANGES_REQUESTED`：保持同一 BASE 修改后重打完整本轮审查包。
- `BLOCKED`：缺少旧库/规则证据/测试环境或存在关键数据错误；不得冒充完成，经用户批准可转做无依赖任务。

## 6. 交付后维护

- **日常**：检查上次成功备份、最新行情时间、后台任务状态、未对账差额。
- **每次升级前**：正式库一致性备份 + 迁移预演 + 明确升级与回滚命令。
- **定期**：从独立副本恢复到测试位置，运行数据库完整性、成交/财务对账，不直接覆盖正式库。
- **每次新需求**：先修改最小的产品契约、验收 ID，然后按上述 Agent 增量审查循环实现；不一次性引入大批未引用功能。

> **重要限制**：本计划属于执行规格。除当前已有的规范与打包工具外，真实业务代码尚未开发，旧真实数据库也未提供。实现和验收结果必须分阶段如实记录。
